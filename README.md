# 原迹下载器

一个在本机运行的 Web 下载工具：粘贴小红书、抖音、Bilibili 或 YouTube 的主页、播放列表或单条内容链接，自动发现作品，并保存平台当前可提供的最高质量媒体。

它提供实时进度、成功/失败明细、单项重试、全部失败项重试、任务取消和验证码提示。默认按作者创建文件夹，文件名以发布日期开头。

> 请只下载你本人拥有、已获授权或法律允许保存的内容。本项目不绕过 DRM、付费权限、地区限制或私密内容访问控制。

## 主要能力

- 本地 Web GUI，默认只监听 `127.0.0.1:8765`
- 小红书主页滚动发现，以及图片、视频、Live Photo 下载
- 抖音主页与单作品下载，支持普通视频、图文和 Live Photo；逐条校验作者、作品 ID 和媒体 ID，避免主页内容串号
- Bilibili 主页、播放列表和单视频下载
- YouTube 频道、播放列表、普通视频与 Shorts 下载
- 视频不设置 720p、1080p、2K 或 4K 上限，自动探测并选择平台实际可提供的最高质量
- 小红书优先使用 direct CDN 原图和 `originVideoKey` 原视频地址
- 不压缩、不重编码；分离的视频流与音频流仅由 FFmpeg 合并封装
- 默认读取 Chrome Cookie，支持登录内容和常见风控场景
- 验证码或登录失效时显示 `等待验证`，完成验证后可重试
- 每个作品显示下载进度、成功/失败状态和失败原因；平台可提供时还会显示速度、ETA 与最终分辨率，多图与 Live Photo 作品可展开查看每个已保存文件
- 失败项可以逐个重试，也可以一键全部重试
- 任务状态保存在本机，程序异常退出后可继续处理失败项
- 启动、安装依赖和后台运行共用内核单实例锁；关闭启动终端或启动器异常退出时，受管进程会先尝试安全停止并在超时后整组回收，不会长期遗留假运行状态

## “平台最高可用”和“不压缩”的含义

本项目不会人为限制分辨率：有 4K 就选 4K，有 2K 就选 2K，否则继续选择平台返回的下一档最高质量。

- YouTube 和 Bilibili 使用 `bestvideo*+bestaudio/best`，不添加最大高度条件。
- 抖音不会相信网页的“2K/4K”标签或 `yt-dlp` 的默认格式排序：工具从已经校验作者和作品 ID 的数据中取得唯一媒体 ID，同时把作者作品接口中最高像素的 direct rendition（不同编码、码率保持独立）与同一媒体 ID 的 `default` 原始档作为两条权威来源，逐条用 FFprobe 检查实际像素、编码、码率、文件大小和时长，再按实际质量选择最高者。`4k`、`2k`、`1080p`、`720p` 标签端点实测经常全部回落到同一条 720p 派生流，不能为最高画质增加有效证据，因此不再把它们的成功与否作为下载条件。普通视频和 Live Photo 都直接逐字节下载刚验证过的最终地址；初始地址必须来自严格白名单内的已签名作者数据或固定 `amemv` 原始档，程序会关闭自动跳转并逐跳检查每个 `Location`，下一跳只有落在明确列出的抖音/字节视频 CDN 后缀，且使用无账号信息、无自定义端口的 HTTPS 地址时才会真正发出请求、读取和保存。`Location` 中直接写出的 IP、本地或保留用途域名不会收到下一跳请求；可信域名仍由系统 DNS 和代理解析，并依赖 HTTPS 证书校验。若前 256 KiB 不足以解析文件尾部的 MP4 元数据，程序会从同一受信来源取得逐字节一致的临时完整文件，并只让 FFprobe 读取本地文件；临时文件在探测后立即清理。完整传输后再次核对精确字节数、前 256 KiB SHA-256、视频/音频 codec、实际分辨率、码率和严格时长指纹，全部一致才原子替换目标文件。author-feed、`default`、地域 CDN 或正式文件传输遇到 timeout、401/403/404/410/429、临时 5xx 或未知 CDN 重定向时会有限退避或立即暂停整条任务，并保留后续排队项，不会连续制造整页失败，也不会趁机下载低清版本；错误详情会区分非 HTTPS、IP 地址、内网或保留域名、异常端口、地址格式错误、已知但缺校验绑定的 CDN 和未识别的 CDN。已知但缺作品绑定的 CDN 只显示固定白名单域名族；未知域名不显示任何原始标签，只显示不可逆短指纹，完整提示会自动换行。缺少结构化 author-feed direct rendition 的新旧任务会先重新发现，绝不只凭 `default` 静默完成。
- 抖音图文只接受作品数据中可信域名的最高像素 `images[].url_list`，逐字节写入响应内容，不在本地转码或重压缩。给定测试主页当前返回的是带 `q75` 标记的 WebP/JPEG 平台派生文件；无 `qNN` 的 `download_url_list` 实测会把部分 1438×2558 图片降为 1080×1920，不能作为更高质量替代。工具因此能保证“平台当前可访问的最高像素文件 + 本地不二次压缩”，不能声称取得作者上传前的无损母版。
- 小红书视频优先使用 `originVideoKey`，再按像素、码率和文件大小选择可用流；下载后使用 FFprobe 核对实际分辨率，原视频地址若临时返回低清文件会继续尝试下一候选而不是静默保存。
- 小红书图片优先重建 direct CDN 地址，网页中的 DFT/PRV 图片只作为最后回退；每个候选都会读取文件本身的像素尺寸，低于作品声明尺寸的占位图会被拒绝。
- JPEG、PNG、WebP、AVIF、GIF 和 HEIC 根据文件 magic bytes 保存，不转换格式。原图是 HEIC 时会保留 `.heic`，部分系统图片查看器可能无法直接预览。
- FFmpeg 合并音视频流属于 remux，不会重编码或压缩画面。

“下载过程不压缩”是指程序保存平台返回的媒体字节，或仅用 FFmpeg 做不重编码的封装合并；它不代表平台文件本身从未压缩，也不代表作者上传前的本地母版。会员等级、登录状态、地区、视频编码和平台接口返回结果都可能影响最高可用清晰度。尤其是抖音，界面显示的“2K”属于质量档位名称，实际文件可能仍是 1080×1920；工具显示和选择时以媒体流实测像素为准。

## 运行前准备

需要：

- [Python](https://www.python.org/downloads/) 3.10 或更高版本
- [Google Chrome](https://www.google.com/chrome/)
- [FFmpeg](https://ffmpeg.org/download.html)
- 首次启动时可访问 PyPI，以安装 Python 依赖；其中会自动包含 YouTube 完整格式发现需要的 Deno runtime

先确认：

```bash
python3 --version
ffmpeg -version
ffprobe -version
```

macOS 可使用 Homebrew 安装 FFmpeg：

```bash
brew install ffmpeg
```

Apple Silicon Mac 的 Homebrew 通常把 `ffmpeg` 和 `ffprobe` 安装到 `/opt/homebrew/bin`。`start.command` 会自动把该目录加入 `PATH`；如果画质探测仍提示找不到 FFprobe，请完全停止旧进程，再重新双击 `start.command`。

Ubuntu/Debian 可使用：

```bash
sudo apt update
sudo apt install ffmpeg
```

Windows 请安装 FFmpeg，并确保 `ffmpeg.exe` 所在目录已经加入 `PATH`。

## 傻瓜式启动

### macOS

双击 `start.command`。首次运行会创建 `.venv`、安装依赖、启动服务，并自动使用 Chrome 打开：

```text
http://127.0.0.1:8765
```

如果系统没有给脚本执行权限，在项目目录运行一次：

```bash
chmod +x start.command start.sh
./start.command
```

### Windows

双击 `start.bat`。脚本使用 Windows Python Launcher `py` 创建本地虚拟环境，然后自动启动 Web 工具。

### Linux

```bash
chmod +x start.sh
./start.sh
```

正常停止时，在启动它的 Terminal 中按 `Ctrl+C`；程序会先取消正在执行的任务、等待当前子步骤收尾，再释放端口和运行状态。macOS/Linux 关闭这个 Terminal 时，父进程监控会触发同样的安全停止；Windows 关闭控制台窗口时，即使系统不给应用完整的优雅退出时间，Job Object 也会回收受管后端和子进程，不会留下永久占锁的后台。

如果启动窗口已经找不到，在 macOS 双击 `stop.command`。它会先核对随机实例 ID、PID、端口、build ID 和只保存在本机的停止密钥，全部一致才通知该后台退出；不会按名称批量终止 Python、FFmpeg 或 Chrome。Windows 双击 `stop.bat`，Linux 运行：

```bash
./stop.sh
```

## 使用方法

1. 在 Chrome 中登录你需要使用的平台；小红书和抖音尤其建议先访问一次目标主页。
2. 启动工具，确认“自动读取 Chrome Cookie”处于开启状态。
3. 如有需要，修改下载目录并保存设置。
4. 粘贴主页、播放列表或单条内容链接，点击“开始下载”。
5. 在“下载明细”中查看每一项的进度、清晰度、成功状态或错误原因。
6. 单个作品失败时点击该行的“重试”；多个作品失败时点击“重试全部失败项”。已经保存成功的多图或 Live Photo 文件会保留并列在作品下方。

取消会在当前网络请求或 FFmpeg 合并步骤结束后安全停止，因此极端情况下按钮状态可能需要等待几十秒；界面会明确显示“正在等待当前步骤停止”，已经完成的文件不会删除。

默认测试案例：

```text
https://www.xiaohongshu.com/user/profile/5c99d4b30000000011015e6d
```

## Chrome Cookie 与验证码

Cookie 默认从本机 Chrome 读取，不会导出为 `cookies.txt`，也不会上传到远程服务器。应用配置和任务状态分别保存在 `data/config.json` 与 `data/state/`；其中不保存 Cookie 值。`data/runtime/` 只保存本次本机进程的运行身份和随机停止密钥，并会在正常退出时删除；macOS/Linux 会把这些记录设为仅当前用户可读写，Windows 则继承项目目录的本机 ACL。

在 macOS 上，系统可能询问是否允许访问 Chrome 的加密 Cookie，请按你的安全判断授权。如果提示 Cookie 数据库被占用、复制失败或解密失败，可以先完全退出 Chrome，再重新启动工具。为避免把匿名访问得到的较低清晰度误当成最终结果，Cookie 开关开启时不会静默回退到匿名下载；如果你明确希望不登录下载，可以在设置中关闭 Chrome Cookie 后重新创建任务。

出现 `等待验证` 时：

1. 点击“打开 Chrome 验证”，或使用普通 Chrome 打开任务的原始主页或视频链接。工具始终使用你提交的原始任务地址，不会用接口响应中的其他作品地址替换它。
2. 完成登录、滑块、短信验证或图形验证码。
3. 确认页面已经能够正常播放或浏览作品。
4. 回到 Web 工具，点击“我已完成，继续重试”或重试对应失败项。

应用不会自动破解验证码。抖音作者接口也可能返回 HTTP 200 但暂时不给作品列表，这通常是独立于验证码的短时限流。程序会串行执行签名请求以避免多个任务同时冲击接口，切换请求页大小、在同一签名会话内退避，并用全新签名会话冷却重试；仍未恢复时会明确显示“短时限流”，保留重试按钮且不打开作者主页，也不会改下低清版本。小红书的“访问频繁”、页面超时、空白响应或 `xsec_token` 失效也会作为普通可重试失败处理，主页重试时会重新获取作品令牌。只有可信站点明确显示登录或验证码页面时才显示 `等待验证`。频繁连续抓取仍可能再次触发风控。

## 文件结构与命名

默认下载到项目内的 `downloads/`，并按作者分文件夹：

```text
downloads/
└── 作者名称/
    ├── 2025-11-14-视频标题 [media-id].mp4
    ├── 2025-11-14-图文标题 [note-id]-001.webp
    └── 2025-11-14-图文标题 [note-id]-002.heic
```

命名规则：

- 日期固定放在最前面，格式为 `YYYY-MM-DD`。
- 日期后是作品标题，尾部保留媒体 ID，避免同名覆盖。
- 多图笔记追加 `-001`、`-002` 等顺序号。
- 平台没有返回日期时使用 `Unknown-Date`。
- 文件夹名和文件名会清理 Windows/macOS/Linux 不允许的字符，但保留中文。
- 重复创建同一任务时会重新获取平台当前提供的最高质量，并替换同名媒体，避免已有低清文件阻止后续升级；写入中的临时文件不会作为完成结果。

早期版本创建的部分抖音任务没有保存足够的作者归属或媒体身份。升级后，无来源证据的历史结果会被隔离且不可重试；已有作者但缺少完整媒体缓存的主页队列会移除未保存的数字占位项，并在继续任务时从原主页重新发现。v1.2.2 保存的旧媒体跳转错误没有记录实际 CDN 主机，v1.2.4 的部分旧格式则保存过完整主机名；当前版本恢复任务时会清除这类旧主机信息。完整主页或视频链接任务会在重试时重新发现，已完成项目保持完成且不会重下；旧抖音短链因缺少当时解析目标的绑定证据，会保留已有文件并要求从原短链新建任务。当前版本再次拦截未知 CDN 时会只显示校验指纹、暂停后续队列且不会误报 Chrome 验证。已经保存的文件不会被自动删除。重新发现后仍不存在的旧条目会显示为“已跳过”且不再反复下载；匹配到的作品会使用新标题、作者、日期和媒体类型重新处理。小红书单作品或短链接若在运行中出现作品串号，也会在下载前拦截并记录为可重试状态；单项重试或全部重试会从最初提交的链接重新发现，不会重复处理错误队列。

## 常见问题

### 为什么更新后打开的还是旧后台？

旧程序不会因为 `git pull` 自动退出。新版本会在创建 `.venv`、执行 `pip install` 之前取得项目级单实例锁，因此即使两次双击启动脚本或选择不同端口，也只会存在一个任务管理器。当前版本已运行时，再次启动会识别同一实例；build 不同时会要求先安全停止，绝不会直接杀死未知进程。

请先回到原 Terminal 按 `Ctrl+C`；窗口已丢失时，双击 `stop.command`，然后重新运行 `./start.command`。macOS 上若升级前的旧版后台没有运行身份记录，停止脚本只会在默认端口 `8765`、唯一监听 PID、当前用户、项目目录、`run.py` 命令和健康身份全部连续核对一致后发送一次 `SIGTERM`，任一条件不符都会拒绝操作。如果仍需只读查看端口：

```bash
lsof -nP -iTCP:8765 -sTCP:LISTEN
```

`data/runtime/project.lock` 文件留在磁盘上是正常的；macOS/Linux 使用它承载内核 advisory lock，Windows 使用与项目路径绑定的 named Event（保证同一 Windows 登录 session 内单实例），文件存在本身不代表程序仍在运行。启动器、依赖安装守护和后端退出后，操作系统会释放实际所有权，下一次启动可以正常取得，因此不会因为一个陈旧文件永久显示 “already starting, installing, running, or shutting down”。如果确有活动实例，启动器只报告状态或打开同一版本页面，不会用 `pkill`、端口盲杀或进程名匹配清理。请用自己的普通账号运行，不要用 `sudo` 或 Administrator 权限启动。

页面右上角会显示 `v版本号 · build ID`。页面、已加载的 Python 后台和磁盘源码任一版本不一致时，界面会显示红色“后台未重启”提示，并禁用创建和重试，避免新版界面继续调用旧版解析逻辑。重启后仍看到提示时，按 `Command+Shift+R` 强制刷新一次。

### 为什么只有 1080p，没有 2K/4K？

工具没有设置分辨率上限。通常原因是平台本次只向当前账号返回到 1080p、账号没有对应权限、Cookie 失效、地区限制，或原作品本身没有更高版本。Bilibili 的部分 4K/HDR/高码率格式需要登录或会员权限。抖音的“2K”标签不保证文件像素达到 1440p，而且真正的最高画质有时位于 `default` 原始档而不是 `2k` 参数：工具会同时探测并以实际字节为准，不会把标签伪报成 2K，也不会漏掉独立的 1440×2560 原始档。

### 为什么所有抖音作品都提示最高画质无法验证？

如果所有作品同时失败，先看错误是否明确写着“短时限流”：这种情况请停止连续测试，等待一两分钟后点击重试，不需要先打开作者主页。如果不是，再在启动程序的同一个终端执行 `ffprobe -version`。抖音画质探测必须使用 FFprobe 读取媒体的真实分辨率；macOS 可运行 `brew install ffmpeg` 安装，然后完全停止程序并重新运行 `./start.command`。当前版本也会在任务错误中分别显示 FFprobe 缺失、网络超时、HTTP、非视频响应、MP4 文件头、时长不匹配等安全诊断，不再只显示一条笼统错误。

### 为什么抖音任务会出现很多纯数字作品？

旧版本有两条已修复路径：视频页异常包装成博主列表时，可能把其他作品加入单视频任务；主页图文也曾被误当成普通视频，继而把作品顶部的音乐播放地址当作视频地址，只能显示作品 ID。当前版本先区分普通视频、图文和 Live Photo，并要求每项同时通过主页作者、作品 ID、规范化来源 URL 和唯一媒体 ID 校验；单视频任务只能包含目标 `/video/<视频 ID>`，Chrome 验证也始终打开用户提交的原视频。更新并彻底重启后，历史数字占位队列会安全迁移；已有文件不会删除。如果旧状态已经丢失原始视频来源，程序不会猜测目标或打开某个博主主页，请重新粘贴原始链接创建任务。

### 为什么抖音旧任务可能显示需要人工检查？

早期版本从整个网页收集视频链接，极端情况下可能混入页面推荐的其他作品。当前版本只接受目标主页接口中作者 `sec_uid` 一致的作品，并在下载前再次核对作品 ID、作者 ID 和媒体 ID。由于旧状态缺少这组证据，程序不会把旧结果自动视为可信；请新建任务重新下载并人工处理旧文件。

### 为什么 YouTube 下载时报 FFmpeg 错误？

YouTube 的最高画质经常把视频与音频分开提供。请安装 FFmpeg，确认终端执行 `ffmpeg -version` 成功，然后重试失败项。

### 为什么 Bilibili 报 412？

这通常是请求被站点风控拦截。先在 Chrome 登录并正常打开目标页面，保持 Cookie 开关开启，稍后重试；不要高频重复创建相同任务。

### 为什么小红书发现的数量每次略有不同？

主页会实时更新、置顶内容可能变化，滚动接口也可能受网络和风控影响。工具会持续滚动，直到连续多轮没有新作品；如明显少于浏览器中可见数量，请完成验证后重试。

### 为什么 HEIC 图片打不开？

这是为了保留平台提供的原始文件，工具不会把 HEIC 转成 JPEG。请使用支持 HEIC 的系统或查看器；如需转换，请在下载完成后另行制作副本，避免修改原始文件。

### 任务失败后，已经成功的文件会丢失吗？

不会。取消任务或重试失败项不会删除已完成文件。批量重试只重新处理失败、等待验证或已取消的项目。

## 测试

离线测试使用 mock `yt-dlp` 与 mock 下载引擎，不依赖外部网站：

```bash
python -m pip install -r requirements-dev.txt
pytest
```

覆盖范围包括：

- 四个平台 URL 识别、分享文本解析和相似恶意域名拒绝
- 作者目录与跨平台文件名清理
- 日期前缀、多图顺序号和媒体 magic bytes 扩展名识别
- 未限高的最高格式参数与 4K 进度事件
- 抖音主页作者隔离、普通视频/图文/Live Photo 分类、作品 ID/唯一媒体 ID 防串号、SecSDK 签名响应校验、限流退避、真实分辨率探测和旧任务安全迁移
- Chrome Cookie epoch 转换、读取失败提示与显式匿名模式
- 小红书原图候选、原视频、Live Photo 与验证码页解析
- 实时进度、任务状态持久化、单项重试和全部失败项重试
- 单实例端口占用、前后端 build 一致性，以及旧抖音数字队列从可信原主页安全迁移
- 启动器、依赖安装守护、后端和子进程树在正常停止、父进程消失、`SIGKILL` 与卡死关闭时的端口和锁回收

## 隐私、安全与免责声明

- 服务默认只监听本机回环地址，媒体和任务数据不经过第三方中转服务器。
- 下载链接、标题和本地输出路径会写入 `data/state/`，Cookie 值不会写入项目状态文件。
- 不要提交 `data/`、`downloads/`、Cookie 文件或含私人链接的日志；这些目录已加入 `.gitignore`。
- 你需要自行遵守各平台服务条款、版权法、隐私权、肖像权和所在地区法律。
- 不要批量抓取你无权保存的内容，不要将下载内容用于骚扰、监控、盗版或未经授权的再分发。
- 本项目按现状提供；网站改版、风控升级或上游 `yt-dlp` 变化都可能暂时导致功能失效。

## 技术栈

- FastAPI + Uvicorn：本地 API、静态页面与 SSE 实时事件
- `yt-dlp` + Deno runtime：YouTube、Bilibili、抖音单视频及完整媒体格式选择
- Playwright + Chrome：小红书/抖音主页发现
- FFmpeg：最高质量分离音视频流的无重编码合并
- Pydantic + JSON：任务模型与本地状态持久化
